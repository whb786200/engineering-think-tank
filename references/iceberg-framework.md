# Iceberg OS 思维框架 · 工程人智库

> 源自地缘政治分析框架 Iceberg OS v1.0，迁移至工程管理场景。

---

## 核心概念：冰山模型

```
        表象层（可见，10%）
    ────────────────────────   ← 海平面
        利益层（不可见，90%）
        权力层（不可见，深层）
        认知层（不可见，最深层）
```

**核心洞见**：大多数分析止步于表象层，真正的洞察在水下。

---

## 四层分析框架

### 第一层：表象层（Surface）

**大多数人看到的信息**
- 公开政策、官方表态、新闻报道
- 表面数据、公开会议结论
- 可以看到的「官方叙事」

**工程场景举例**：
- 项目开工仪式、领导讲话
- 官方发布的进度数据
- 合同文件中的明文条款

**提问方式**：
> 「这件事表面上是什么？」
> 「公开信息告诉了我们什么？」

---

### 第二层：利益层（Interests）

**各方的真实诉求**
- 谁从现状中受益？
- 谁在推动变化？谁在阻挠变化？
- 不同主体的利益如何冲突或一致？

**工程场景举例**：

| 主体 | 表面说法 | 真实利益 |
|------|---------|---------|
| 建设单位 | 「保证质量、按期交付」 | 控制成本、尽快回款 |
| 施工单位 | 「按图施工、质量第一」 | 合理利润、避免返工 |
| 监理单位 | 「独立公正、严格把关」 | 规避责任、维持合作关系 |
| 分包单位 | 「配合总包、保证进度」 | 拿到进度款、避免被清退 |

**提问方式**：
> 「各方真实的利益诉求是什么？」
> 「钱/权/名 流向了哪里？」

---

### 第三层：权力层（Power）

**什么在真正驱动决策**
- 决策权在谁手里？
- 信息如何被过滤和扭曲？
- 正式规则 vs 实际运作规则

**工程场景举例**：
- 变更签证的「实际审批路径」（不一定是合同上的流程）
- 分包选择的「真实决策人」（可能不是项目经理）
- 质量问题的「捂盖子机制」（谁决定上报还是不上报）

**提问方式**：
> 「决策是如何真正做出的？」
> 「绕过正式流程的力量是什么？」

---

### 第四层：认知层（Cognition）

**底层思维模型**
- 决策者的认知框架是什么？
- 过往经验/认知偏差如何影响判断？
- 有没有可复用的分析模型？

**工程场景举例**：
- 项目经理如果出身技术线，可能过度关注技术细节而忽视统筹协调
- 如果出身商务线，可能过度关注成本而忽视质量风险
- 认知模型：「工程=技术+管理+协调」才能做出平衡决策

**提问方式**：
> 「这个决策背后是什么思维模型？」
> 「有没有更深层的认知框架可以迁移？」

## 在工程文章中的运用方式

### 方式一：全文结构按四层展开

```markdown
## 表象层：大多数人看到的[现象]

[描述普遍认知]

## 利益层：各方的真实诉求

| 主体 | 表面说法 | 真实诉求 |
|------|---------|---------|
| ... | ... | ... |

## 权力层：什么在真正驱动决策

[分析决策机制]

## 认知层：我们可以怎么思考

[给出可复用的思维模型]
```

### 方式二：局部运用（某一节用冰山分析）

在文章中间插入一个「冰山分析」板块：

```markdown
> 🧊 **冰山分析**
> 
> **表象**：[表面现象]
> **利益**：[利益分析]
> **权力**：[权力分析]
> **认知**：[认知框架]
```

### 方式三：金句收尾（用冰山观点做结尾）

```markdown
> 💡 **用冰山思维看这个问题：**
> 大多数人只看到[表象]，但真正决定结果的，
> 是水下的[利益/权力/认知]。
> 下次遇到类似情况，不妨多问一句：[核心追问]。
```

## 与工程项目管理结合

### 变更签证中的冰山分析

| 层次 | 分析内容 |
|------|---------|
| 表象 | 设计变更、工程量增加 |
| 利益 | 施工单位想增加造价，建设单位想控制成本 |
| 权力 | 谁有最终审批权？监理的意见有多重要？ |
| 认知 | 变更管理是「零和博弈」还是「目标一致」？ |

### 进度滞后中的冰山分析

| 层次 | 分析内容 |
|------|---------|
| 表象 | 天气原因、材料供应滞后 |
| 利益 | 分包想拖延以争取更多资源投入 |
| 权力 | 项目经理的考核压力 vs 分包的生存压力 |
| 认知 | 「进度滞后=失败」还是「滞后是可管理的风险」？ |

### 质量事故中的冰山分析

| 层次 | 分析内容 |
|------|---------|
| 表象 | 施工操作不规范 |
| 利益 | 抢工期导致质量让步 |
| 权力 | 质量检查是否被「人际关系」软化？ |
| 认知 | 「合格=安全」还是「合格≠无风险」？ |

```
你是一位擅长深度分析的工程管理专家，善于用「冰山模型」分析问题。

请对以下工程场景做四层分析：

[工程场景描述]

要求：
1. 表象层：大多数人会怎么看这件事？
2. 利益层：各方的真实诉求是什么？
3. 权力层：决策是如何真正被做出的？
4. 认知层：有什么可复用的思维模型？

请用表格和短段落结合的方式输出，适合公众号阅读。
```

## 注意事项

1. **不要过度解读**：冰山分析要有依据，不能全是阴谋论
2. **保护隐私**：涉及具体项目/人物时，做脱敏处理
3. **建设性结尾**：分析完后要给出可操作的建议，不能只拆不建
4. **适度使用**：不是每篇文章都需要四层分析，根据选题深度决定
